[[workload-factory-administration-enhancements]]
=== Mejoras en la administración de Workload Factory



==== Comprobar y actualizar los datos del panel de control personalizado

Ahora puedes ver cuándo se actualizaron por última vez las métricas de tu panel personalizado y actualizarlas manualmente. Pasa el cursor por encima de *Actualizar datos* para ver la fecha y la hora de la última actualización.

Selecciona *Refresh data* para iniciar un nuevo escaneo. Aparecerá un mensaje que confirma que el escaneo ha comenzado y el botón permanecerá desactivado hasta que finalice el escaneo.

Cuando haya datos nuevos disponibles, selecciona *Cargar ahora* en el banner de notificación para actualizar el panel de control.

Tanto *Actualizar datos* como *Cargar ahora* generan eventos de recopilación de datos en Tracker.

link:admin/manage-custom-dashboards-fsx.html#refresh-dashboard-data["Descubre cómo actualizar los datos de un panel de control personalizado"]



==== Especifica regiones para paneles personalizados

Los paneles personalizados ahora te piden que elijas una o varias regiones si tu solicitud no las incluye. Los datos del panel se limitan a las regiones que selecciones.

link:admin/create-custom-dashboard-fsx.html["Aprende a crear un panel de control personalizado"]



==== Política de IAM para la creación de enlaces en FSx for ONTAP

La plantilla de CloudFormation y el código de Terraform para crear enlaces ahora usan una política de IAM en lugar de permisos de Lambda integrados.

link:fsx-storage/create-link.html["Aprende a crear un enlace"]



==== Auditoría y seguimiento de las acciones de los agentes de IA

Ahora puedes usar Tracker para revisar los cambios en la configuración del agente de IA y, en modo de lectura/escritura, cada solicitud de aprobación, incluida la pregunta del agente y la respuesta del usuario.

El servicio Workload Factory que realiza la operación registra los cambios en los recursos realizados a través de las API de Workload Factory.

link:admin/learn-agent.html#audit-and-tracking-for-agent-actions["Infórmate sobre la auditoría y el seguimiento de las acciones de los agentes"]



[[amazon-fsx-for-netapp-ontap-enhancements]]
=== Mejoras de Amazon FSx for NetApp ONTAP



==== Mejoras en el diagrama del grupo de iniciadores

El diagrama que muestra los grupos de iniciadores para los dispositivos de bloque en la página «Gestionar acceso de clientes» incluye ahora más detalles sobre los hosts. Al pasar el cursor sobre un host en el diagrama, aparecen sus detalles, incluidos el nombre de host, el ID de instancia, el tipo de carga de trabajo, la región y el iSCSI Qualified Name (IQN).



==== Mejora del correo electrónico para incidencias de arquitectura óptima

El nuevo diseño del correo electrónico ofrece más detalles y contexto sobre los problemas de configuración detectados por Workload Factory. El correo incluye el número de recursos analizados, cuántos presentan problemas de advertencia o críticos, y cuáles son esos problemas. El correo también incluye un enlace al panel de control «well-architected» de FSx for ONTAP para que puedas resolver los problemas de inmediato.



==== Mejoras del panel Well-architected



===== Compatibilidad con determinadas comprobaciones de configuración

Puedes ejecutar manualmente el análisis en las configuraciones seleccionadas de modo que solo analices las configuraciones que te interesan y reduzcas el tiempo de espera.



===== Nuevas recomendaciones en el análisis bien arquitectado

Workload Factory ahora incluye las siguientes configuraciones en el análisis bien arquitectado para los sistemas de archivos FSx for ONTAP:

Para cargas de trabajo de almacenamiento:

* *Conectar el host al nodo de conmutación por error*: comprueba si los hosts están conectados al nodo de conmutación por error en un sistema de archivos FSx para ONTAP activo-pasivo para garantizar la fiabilidad.
* *Conectar el host al nodo preferido*: comprueba si los hosts están conectados a sus dispositivos de bloque mediante el nodo preferido para optimizar el rendimiento.
* *Brecha en la detección de múltiples dispositivos en ARP/AI*: ARP/AI ofrece una cobertura de protección completa cuando un volumen solo tiene un dispositivo de bloque conectado. Si un volumen tiene varios dispositivos de bloque conectados, Workload Factory traslada esos dispositivos a volúmenes nuevos para que cada volumen tenga solo un dispositivo de bloque.
* *Limpieza de clones*: comprueba si hay algún clon de volumen con más de 30 días de antigüedad que se pueda eliminar para optimizar el uso del almacenamiento y reducir los costes.
* *Comprobar que el sistema operativo del grupo iniciador (igroup) coincida con el del host*: comprueba si el sistema operativo del grupo iniciador (igroup) coincide con el del host para evitar problemas de E/S o de rendimiento.


Para cargas de trabajo de Kubernetes:

* *Configuración de QoS*: comprueba si una política de QoS de ONTAP protege los volúmenes persistentes de Kubernetes para garantizar la eficiencia del rendimiento.
* *Máquina virtual de almacenamiento dedicada a Kubernetes*: comprueba si el sistema de archivos utiliza una máquina virtual de almacenamiento dedicada a las cargas de trabajo de Kubernetes para mejorar el aislamiento y simplificar la gestión del almacenamiento.
* *Política de exportación dedicada de Kubernetes*: comprueba si cada volumen persistente de Kubernetes cuenta con una política de exportación dedicada que solo permite el acceso desde los nodos worker del clúster.
* *CHAP bidireccional para los backends iSCSI de Kubernetes*: comprueba si los backends iSCSI de Trident tienen habilitada la autenticación CHAP mutua por motivos de seguridad.
* *Desactivar `showmount` en la máquina virtual de almacenamiento de la aplicación*: comprueba si `showmount` está desactivado en la máquina virtual de almacenamiento de la aplicación para evitar que los clientes muestren en la lista las exportaciones a las que no pueden acceder.


Para cargas de trabajo de bases de datos:

* *Política de Snapshot de SAP HANA*: comprueba si la política de Snapshot está configurada en "None" para los volúmenes de SAP HANA para reducir los costes de almacenamiento y mejorar el rendimiento de los datos activos de la base de datos.
* *Política de Snapshot de MySQL*: comprueba si la política de Snapshot está configurada en «Ninguna» para los volúmenes de MySQL, con el fin de reducir los costes de almacenamiento y mejorar el rendimiento de los datos de la base de datos activa.
* *Política de snapshots de PostgreSQL*: comprueba si la política de snapshots está configurada en «None» para los volúmenes de PostgreSQL a fin de reducir los costes de almacenamiento y mejorar el rendimiento de los datos activos de la base de datos.




===== Valores actuales y recomendados para las configuraciones

Puedes consultar los valores actuales y recomendados para algunas configuraciones no optimizadas en el dashboard de Well-Architected. Esto te indica cuál es el valor recomendado antes de corregirlo.

* Jerarquización de datos inactivos
* Política de SnapVault
* Margen de capacidad del SSD




==== Mejoras en los costes



===== Previsión de costes y análisis

Ahora puedes realizar previsiones de costes para tus sistemas de archivos FSx for ONTAP mediante la función de previsión de costes. Esto te ayuda a planificar tu presupuesto y a optimizar tus recursos de forma eficaz. También puedes consultar información detallada sobre tus costes y patrones de uso para identificar oportunidades de optimización de costes.



===== Informes de costes y uso de AWS (CUR)

Workload Factory ahora usa AWS Cost and Usage Reports (CUR) en lugar de AWS Cost Explorer para proporcionar registros de facturación detallados que se entregan a buckets de S3 propiedad del cliente. CUR ofrece una mejor granularidad de costes y sirve como base para casos de uso avanzados de FinOps, chargeback y asignación de costes.



==== Mejoras en la migración de máquinas virtuales de almacenamiento

Workload Factory ofrece una guía mejorada en la interfaz de usuario para migrar VM de almacenamiento. Esto incluye instrucciones paso a paso y una prueba antes de confirmar la migración en producción.

link:fsx-storage/create-replication.html["Más información sobre la migración de VM de almacenamiento"]



==== Mejora de las notificaciones por correo electrónico sobre el retraso en la replicación

Cuando se produce un gran número de incidencias relacionadas con el retraso en la replicación, Workload Factory las agrupa automáticamente en una única notificación por correo electrónico para que no te veas desbordado por las notificaciones.



==== Mejora de la gestión automática de la capacidad

Ahora puedes activar las notificaciones automáticas de gestión de capacidad para probar la función antes de pedirle a Workload Factory que gestione tu capacidad de forma automática. Recibirás una notificación cuando tu sistema de archivos se esté quedando sin capacidad.



==== Configuraciones de bases de datos incluidas en el panel de control Well-Architected

El dashboard well-architected ahora incluye recomendaciones para las configuraciones de tu base de datos, lo que te permite evaluar y optimizar tu configuración según las mejores prácticas. Las primeras configuraciones incluidas en el dashboard son:

* Jerarquización de datos inactivos
* Eficiencias de almacenamiento
* Política de SnapVault
* Margen de capacidad del SSD
* Gestión de espacio de dispositivos de bloque
* Tipo de OS
* Haz coincidir el tipo de sistema operativo del dispositivo de bloques con el del host
* Dispositivos de bloque inactivos (LUNs)
* Ubicación de los archivos de datos (.mdf)
* Ubicación de los archivos de registro (.ldf)
* Estado de la E/S multivía
* Tiempo de espera de I/O multivía
* Quórum del clúster
* Ajuste de recursos de computación


Selecciona el menú principal en la consola de Workload Factory y, a continuación, selecciona *Well-architected* para acceder al panel de control de Well-architected.

image:well-architected-menu-option.png["Opción de menú bien estructurada en la consola de NetApp Workload Factory"]



==== Puntos de decisión sobre el rendimiento

Ahora puedes consultar las recomendaciones de rendimiento de los clientes y los puntos de decisión de automatización. Pasa el cursor por encima de un punto de decisión para ver detalles, como el SKU actual y el recomendado, o las métricas incumplidas en la ventana de tiempo (%).

[[oci-netapp-storage-service-enhancements]]
=== Mejoras en OCI NetApp Storage Service



==== Análisis de arquitectura bien diseñada para los sistemas OCI NSS

NetApp Workload Factory incluye la evaluación well-architected para los sistemas OCI NSS. La evaluación proporciona información, recomendaciones y correcciones para ayudarte a lograr la excelencia operativa.

Se ofrecen evaluaciones de configuración para los siguientes pilares de OCI Well-Architected Framework:

* Fiabilidad: capacidad del objeto de archivo, política de snapshots y margen de capacidad de SSD
* Excelencia operativa: informes de capacidad visibles para el host y margen de capacidad del volumen
* Optimización de costes: organización en niveles de datos fríos, limpieza de snapshots y eficiencias de almacenamiento


Obtén más información sobre link:oci/configuration-analysis.html["el análisis de arquitectura adecuada para los sistemas OCI NSS"] y sobre link:oci/improve-configurations.html["implementar configuraciones bien diseñadas"].
