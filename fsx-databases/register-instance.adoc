= Registrar recursos en NetApp Workload Factory for Databases
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Registra instancias de Microsoft SQL Server y bases de datos de Oracle para que puedas gestionar tus recursos, crear bases de datos y clones de sandbox, ejecutar análisis de registros de errores y optimizar configuraciones en NetApp Workload Factory for Databases.

Solo puedes registrar tus recursos si se ejecutan en FSx para ONTAP file system storage.



[[about-the-task]]
== Acerca de la tarea

El registro de una instancia (SQL Server) o una base de datos (Oracle) consta de dos pasos: la autenticación de la instancia o la base de datos y la preparación. La autenticación es el proceso de verificar las credenciales de la instancia o la base de datos. La preparación incluye la instalación de los módulos de AWS, NetApp y PowerShell en la instancia o la base de datos, para cumplir los requisitos mínimos de Workload Factory for Databases, como link:create-sql-database.html["crear una base de datos"], link:create-sandbox-clone.html["crear un entorno de pruebas"], link:analyze-error-logs.html["análisis de registros de errores"] o link:optimize-configurations.html["la evaluación bien diseñada"].

Workload Factory solo admite el registro y la administración de instancias de Microsoft SQL Server y Oracle. Dependiendo de las credenciales de la cuenta de AWS que elijas en Workload Factory, los hosts PostgreSQL aparecen en el inventario. Actualmente, Workload Factory admite instancias PostgreSQL no registradas que se ejecutan solo en sistemas operativos Amazon Linux.



[[before-you-begin]]
== Antes de empezar

Antes de registrar una instancia o una base de datos, debes hacer lo siguiente:

* Asegúrate de que los hosts de los recursos que deseas registrar aparezcan en el inventario. link:../fsx-storage/add-credentials.html["Concede permisos de _operaciones y corrección_"^] en tu cuenta de AWS.
* Asocia un enlace al sistema de archivos FSx for ONTAP que aloja los recursos que deseas registrar. link:../fsx-storage/create-link.html["Descubre cómo asociar un enlace ya existente o crear y asociar un nuevo enlace."^] Una vez asociado el enlace, vuelve a esta operación.




[[registering-an-instance-in-a-private-network]]
=== Registrar una instancia en una red privada

Para registrar una instancia o base de datos en una red privada sin conectividad externa, haz que los endpoints necesarios estén disponibles en la VPC y asígnalos a las subredes correspondientes. Permite el puerto 443 en el Security Group para los endpoints de interfaz.

* `S3 Gateway/endpoint`
* `ssm`
* `ssmmessages`
* `fsx`
+
Si usas un servidor proxy para las conexiones EC2 salientes, permite el acceso a estos dominios para las operaciones de gestión:

* ``.microsoft.com`` (SQL Server)
* ``.powershellgallery.com`` (SQL Server)
* ``.aws.amazon.com``
* ``.amazonaws.com``




[[register-a-microsoft-sql-server-instance]]
== Registrar una instancia de Microsoft SQL Server

Registrar una instancia tiene dos pasos: la autenticación de la instancia y la preparación. Puedes registrar una sola instancia o varias instancias.

Workload Factory admite el registro para Failover Cluster Instance (FCI) y la implementación autónoma para SQL Server.

.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa se utiliza para ir a Workloads, la opción del menú de Workload Factory"], *Cargas de trabajo* > *Bases de datos*.
. En el menú «Bases de datos», selecciona *Inventario*.
. En el Inventario, selecciona *Microsoft SQL Server* como tipo de motor.
. Selecciona la pestaña *Instancias*.
. Selecciona si deseas registrar una sola instancia o varias instancias.
. Para autenticar instancias (paso 1), haz lo siguiente y luego selecciona *Siguiente*:
+
.. Selecciona *usar las mismas credenciales para todas las instancias* o *gestionar credenciales manualmente*.
.. Autentica SQL Server y Windows proporcionando el nombre de usuario y la contraseña.
+
Si las instancias están autenticadas, selecciona *Siguiente*.



. Para preparar (paso 2), asegúrate de que la(s) instancia(s) cumple(n) los requisitos mínimos.
+
Para cumplir los requisitos mínimos, la instancia debe tener instalados los módulos de AWS y NetApp PowerShell y los módulos de PowerShell 7, y debes completar los requisitos previos para al menos una de las capacidades enumeradas en Prerequisite check.

+
.. Revisa los prerrequisitos en la *Prerequisite check view*.
+
Debes completar todos los requisitos previos para una sola capacidad como *Revisar problemas y recomendaciones bien diseñados* para registrar la instancia.

.. Selecciona *Detalles de configuración* para cada capacidad para conocer los requisitos previos de la capacidad y sigue las instrucciones en pantalla para completar cualquier requisito previo que falte para una capacidad.
+
Para habilitar Workload Factory para link:optimize-configurations.html["revisa y soluciona los problemas bien arquitectados"], completa todos los requisitos previos en *Revisar problemas y recomendaciones bien diseñados* y *Corregir problemas bien diseñados*.



. Después de completar todos los requisitos previos, *Registra* la(s) instancia(s).


.Resultado
Se inicia el registro de la instancia. Selecciona la pestaña *Job monitoring* para seguir el progreso.



[[register-an-oracle-database]]
== Registrar una base de datos Oracle

Registrar una instancia tiene dos pasos: la autenticación en la base de datos y la preparación. Puedes registrar una sola instancia o varias bases de datos.

.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa se utiliza para ir a Workloads, la opción del menú de Workload Factory"], *Cargas de trabajo* > *Bases de datos*.
. En el menú «Bases de datos», selecciona *Inventario*.
. En el Inventario, selecciona *Oracle* como tipo de motor.
. Selecciona la pestaña *Bases de datos*.
. Selecciona esta opción para registrar una sola base de datos o varias bases de datos.
. Para autenticar bases de datos (paso 1), haz lo siguiente y luego selecciona *Siguiente*:
+
.. Selecciona *usar las mismas credenciales para todas las instancias* o *gestionar credenciales manualmente*.
.. Autentica al usuario de Oracle y al usuario de Automatic Storage Management (ASM) grid (si aplica) proporcionando el nombre de usuario y la contraseña.
+
Si las bases de datos están autenticadas, selecciona *Siguiente*.



. Para preparar (paso 2), asegúrate de que la(s) base(s) de datos cumple(n) los requisitos previos. Si todos los módulos requeridos están instalados y se cumplen los requisitos previos, selecciona *Next* para registrar la base de datos. De lo contrario, sigue estos pasos.
+
.. Revisa los prerrequisitos en la *Prerequisite check view*.
+
Debes completar todos los requisitos previos para una sola capacidad como *Revisar problemas y recomendaciones bien diseñados* para registrar la base de datos.

.. Selecciona *Detalles de configuración* para cada capacidad para conocer los requisitos previos de la capacidad y sigue las instrucciones en pantalla para completar cualquier requisito previo que falte para una capacidad.
+
Para tener Workload Factory link:optimize-configurations.html["revisa y soluciona los problemas bien arquitectados"] para tus bases de datos, completa todos los requisitos previos que aparecen en *Revisar problemas y recomendaciones bien diseñados* y *Corregir problemas bien diseñados*.



. Después de completar los requisitos previos, *Registra* la(s) base(s) de datos.


.Resultado
Se inicia el registro de la base de datos. Selecciona la pestaña *Job monitoring* para seguir el progreso.

.Qué sigue
Después de registrarte, puedes realizar estas tareas.

* Ver bases de datos del inventario
* link:create-sql-database.html["Crear una base de datos"]
* link:create-sandbox-clone.html["Crear un clon de la base de datos (entorno de pruebas)"]
* link:optimize-configurations.html["Obtén una evaluación exhaustiva y bien estructurada de las configuraciones de bases de datos"]
