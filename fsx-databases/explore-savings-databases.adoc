= Explora el ahorro en NetApp Workload Factory para bases de datos
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Descubre el ahorro en NetApp Workload Factory for Databases para tus cargas de trabajo de bases de datos comparando los costes de usar Microsoft SQL Server en Amazon Elastic Block Store (EBS), FSx for Windows File Server y el almacenamiento on-premises con almacenamiento FSx for ONTAP.



[[about-this-task]]
== Acerca de esta tarea

Puedes explorar ahorros para tus cargas de trabajo de bases de datos en EBS, FSx for Windows File Server y almacenamiento local usando el Dashboard, la pestaña Inventory o la pestaña Explore savings. En todos los casos, puedes usar la savings calculator para comparar varios componentes de coste al ejecutar cargas de trabajo de Microsoft SQL Server, como almacenamiento, cómputo, licencia de SQL, instantáneas y clones para tus cargas de trabajo de bases de datos en sistemas de archivos FSx for ONTAP frente a Elastic Block Store (EBS), FSx for Windows File Server y almacenamiento local.

Si Workload Factory encuentra ahorros en FSx for ONTAP, puedes implementar Microsoft SQL sobre FSx for ONTAP directamente desde la calculadora de ahorros en la consola de Workload Factory. Cuando tienes varias instancias de Microsoft SQL Server sobre Elastic Block Store, FSx for Windows File Server o almacenamiento local, te recomendaremos una configuración de FSx for ONTAP con una sola instancia de SQL.

.Ahorros potenciales para todas las cargas de trabajo de bases de datos
Visita el *Dashboard* de bases de datos en la consola de Workload Factory para obtener una visión general del ahorro potencial de costes al ejecutar todas tus cargas de trabajo de bases de datos en FSx for ONTAP. El mosaico *Potential savings* muestra tus cargas de trabajo de bases de datos en EBS y FSx for Windows File Server, el ahorro potencial de costes, el porcentaje de ahorro y un gráfico de barras.

image:screenshot-dashboard-potential-savings-tile.png["Captura de pantalla del mosaico «Ahorros potenciales» del panel de bases de datos en la consola de Workload Factory. El mosaico «Ahorros potenciales» muestra el número total de cargas de trabajo de bases de datos que tienes en Elastic Block Store y FSx for Windows File Server, el ahorro potencial, el porcentaje de ahorro y una representación visual en el gráfico de barras."]

.Calculadora de ahorro
Puedes utilizar la calculadora de ahorro para comparar varios componentes del coste de ejecutar cargas de trabajo de Microsoft SQL Server, como almacenamiento, cómputo, licencia de SQL, instantáneas y clones para tus cargas de trabajo de bases de datos en sistemas de archivos FSx for ONTAP frente a Elastic Block Store (EBS), FSx for Windows File Server y almacenamiento on-premises. FSx for ONTAP puede ser la opción más rentable para tus cargas de trabajo de bases de datos.

La calculadora muestra si el almacenamiento para las cargas de trabajo de bases de datos en estos servidores Microsoft SQL Server costaría menos si usas un sistema de archivos FSx for ONTAP. <<Opciones de la calculadora,Aprende a utilizar la calculadora.>>

image:screenshot-ebs-savings-calculator-update.png["Una captura de pantalla de la página de la calculadora de ahorro muestra, a la izquierda, la configuración seleccionada de Microsoft SQL Server en Amazon Elastic Block Store, junto con la opción de personalizar los valores de snapshots y clones. A la izquierda se muestran el ahorro en dólares y el porcentaje de ahorro, así como el coste mensual total por utilizar Microsoft SQL Server en FSx for ONTAP y el almacenamiento de Elastic Block Store."]



[[sql-server-deployment-analysis]]
== Análisis de la implementación de SQL Server

La calculadora comprueba tu implementación de SQL Server para asegurarse de que los recursos y funciones que usas coinciden con la edición de SQL Server. Aquí tienes los factores y condiciones clave que la calculadora revisa antes de recomendar un downgrade a Standard Edition:

.Modelo de implementación
La calculadora evalúa el modelo de implementación y si se requiere Enterprise edition.

.Recursos asignados
La calculadora evalúa las condiciones de los siguientes recursos asignados sujetos a licencia:

* VCPUs de la instancia de destino: la instancia tiene 48 o menos vCPUs.
* Asignación de memoria: la instancia tiene 128GB o menos de memoria.


.Uso de las funciones de Enterprise
La calculadora comprueba si estás usando alguna de las siguientes funciones de Enterprise:

* Funciones Enterprise a nivel de base de datos
* Operaciones de indexación en línea
* Resource Governor
* Replicación peer-to-peer o Oracle
* Extensiones R/Python
* TempDB optimizada para memoria


Si la instancia de SQL Server evaluada no utiliza ninguna de las características Enterprise mencionadas y cumple las limitaciones de recursos, la calculadora recomendará reducir la licencia a Standard Edition. La calculadora te ayuda a optimizar los costes de licencia de SQL Server sin reducir el rendimiento ni la funcionalidad.



[[calculator-options]]
== Opciones de la calculadora

Hay dos opciones de calculadora disponibles para realizar la comparación de costes entre tus sistemas y FSx for ONTAP: la personalización y la detección.

Descubre cómo ahorrar gracias a la personalización: tú proporcionas los parámetros de configuración para Microsoft SQL server en Amazon EC2 con EBS o FSx for Windows File Server incluyendo la región, el modelo de implementación, la edición de SQL server, la tasa de cambio mensual de datos, la frecuencia de las instantáneas y mucho más.

Explora el ahorro de los hosts detectados: Workload Factory se vincula a tus Microsoft SQL servers existentes y extrae los detalles a la calculadora para compararlos automáticamente. Necesitarás conceder permisos de _view, planning, and analysis_ para usar esta opción de la calculadora. Puedes cambiar el caso de uso, pero todos los demás detalles se determinan automáticamente en el cálculo.

Además, puedes link:../fsx-storage/add-credentials.html["añadir credenciales de AWS"^] para mejorar la precisión del análisis de la calculadora. Selecciona *Calculate savings based on existing resources*. Se te redirigirá a la página Add credentials. Después de añadir credenciales, selecciona los recursos existentes para compararlos con FSx for ONTAP y selecciona *Explore savings*.

==== Personaliza el ahorro para hosts Microsoft SQL Server

Sigue los pasos de la pestaña correspondiente a tu tipo de almacenamiento.

[role="tabbed-block"]
====
.Amazon Elastic Block Store (EBS)
--
.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa se utiliza para ir a Workloads, la opción del menú de Workload Factory"], *Cargas de trabajo* > *Bases de datos*.
. En el menú Bases de datos, selecciona *Explorar ahorros* y luego *Microsoft SQL Server en EBS*.
. En la calculadora de ahorro, introduce los siguientes datos:
+
.. *Región*: selecciona una región del menú desplegable.
.. *Modelo de implementación*: selecciona un modelo de implementación en el menú desplegable.
.. *Edición de SQL server*: selecciona la edición de SQL server en el menú desplegable.
.. *Tasa de cambio mensual de los datos (%)*: introduce el porcentaje medio de variación de los datos de clonación y de instantáneas al mes.
.. *Frecuencia de las instantáneas*: selecciona una frecuencia de instantáneas en el menú desplegable.
.. *Número de copias clonadas*: introduce el número de copias clonadas en la configuración de EBS.
.. *Coste mensual de SQL BYOL ($)*: si lo deseas, introduce el coste mensual de SQL BYOL en dólares.
.. En las especificaciones de EC2, proporciona lo siguiente:
+
*** *Descripción de la máquina*: si lo deseas, introduce un nombre para describir la máquina.
*** *Tipo de instancia*: selecciona el tipo de instancia de EC2 en el menú desplegable.


.. En «Tipos de volumen», introduce los siguientes datos para al menos un tipo de volumen. Las IOPS y el rendimiento se aplican a determinados tipos de volúmenes de disco.
+
*** *Número de volúmenes*
*** *Capacidad de almacenamiento por volumen (GiB)*
*** *IOPS aprovisionadas por volumen*
*** *Rendimiento MB/s*


.. Si has seleccionado el modelo de implementación de disponibilidad Always On, indica los detalles de *las especificaciones de EC2 secundario* y *los tipos de volumen*.

+
Si la página *Explore savings* no carga los datos tras una autenticación correcta, selecciona la pestaña *Inventory* para volver a cargar los datos y, a continuación, vuelve a seleccionar la pestaña *Explore savings*.

+
Workload Factory agrupa varios hosts de SQL Server en una única recomendación de configuración de FSx for ONTAP para optimizar el ahorro de costes, salvo que los hosts EBS seleccionados superen los límites de rendimiento, capacidad o IOPS de un único sistema de archivos FSx for ONTAP.

. En la calculadora de ahorro, puedes dar los siguientes detalles sobre clones e instantáneas en tu almacenamiento EBS para una estimación de ahorro de costes más precisa.
+

.. *Número de copias clonadas*: introduce el número de copias clonadas en la configuración de EBS.
.. *Tasa de cambio mensual*: introduce el porcentaje medio de cambio mensual de los datos de clonación y de instantáneas.
.. *Añadir hosts*: si lo deseas, selecciona hasta cinco hosts EBS detectados para incluirlos en el cálculo del ahorro.

.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].

. Selecciona *Download assessment script*.
+
El script es una herramienta de recopilación de datos basada en PowerShell. Recopila datos de configuración y rendimiento de Oracle Server.

. Ejecuta el script en el host de Oracle con un usuario que tenga privilegios suficientes.
. Selecciona *Upload script results* y luego sube el archivo de salida del script a la consola de Workload Factory. El migration advisor evalúa los datos y planifica el despliegue de FSx for ONTAP para tu entorno de Oracle Server.
. En la pestaña Oracle Server on-premises, selecciona el Oracle Server on-premises y luego selecciona *Explore savings* para ejecutar un análisis de costes frente a FSx for ONTAP.

. Si quieres, proporciona los siguientes datos sobre los clones (copias de sombra) y las instantáneas en tu entorno de bases de datos local para obtener una estimación más precisa del ahorro de costes.
+
.. *Frecuencia de las instantáneas*: selecciona una frecuencia de instantáneas del menú.
+
Si NetApp Workload Factory detecta shadow copies de Amazon FSx for Windows, establece el valor predeterminado en *Daily*. Si no detecta shadow copies, establece el valor predeterminado en *No snapshot frequency*.

.. *Frecuencia de actualización de los clones*: selecciona en el menú la frecuencia con la que se actualizan los clones.
.. *Número de copias clonadas*: introduce el número de copias clonadas en la configuración local.
.. *Tasa de cambio mensual*: introduce el porcentaje medio de cambio mensual de los datos de clonación y de instantáneas.


. Para obtener resultados más precisos, actualiza la información sobre recursos informáticos y los detalles de almacenamiento y rendimiento.
+

Después de haber explorado los ahorros para un host local de Oracle, tienes la opción de eliminar el registro del host local de Workload Factory. Selecciona el menú de acciones del host local de Oracle y luego selecciona *Delete*.

== Implementar Microsoft SQL Server en AWS EC2 utilizando FSx for ONTAP

Si quieres cambiar a FSx for ONTAP para ahorrar costes, haz clic en *Create* para crear la configuración recomendada directamente desde el asistente para crear un nuevo servidor de Microsoft SQL Server o haz clic en *Save* para guardar la configuración recomendada para más adelante.


NOTE: Workload Factory no permite guardar ni crear varios sistemas de archivos FSx for ONTAP.

.Métodos de implementación
Con los permisos de _creación de hosts de bases de datos_, puedes implementar el nuevo Microsoft SQL server en AWS EC2 utilizando FSx for ONTAP directamente desde Workload Factory. También puedes copiar el contenido de la ventana de Codebox e implementar la configuración recomendada utilizando uno de los métodos de Codebox.

Si no tienes permisos, puedes copiar el contenido de la ventana Codebox e implementar la configuración recomendada mediante uno de los métodos de Codebox.
