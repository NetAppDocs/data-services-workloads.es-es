= Replica datos a FSx para ONTAP en NetApp Workload Factory
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Replica los datos en NetApp Workload Factory para protegerte contra la pérdida de datos si la región donde residen tus datos sufre un desastre. La replicación de datos es compatible entre los sistemas de archivos FSx for ONTAP y los sistemas ONTAP locales o Cloud Volumes ONTAP. Workload Factory también admite la replicación en cascada para ampliar la protección de datos a sistemas terciarios o migrar tus datos.

Al replicar datos de almacenamiento VM y ajustes de configuración, primero debes crear e inicializar la relación de replicación y luego esperar a que los datos se sincronicen al menos una vez antes de completar la operación de transición.



[[standard-replication]]
== Replicación estándar

La replicación protege tus datos si un desastre afecta tu región; también puede usarse para migración.

La replicación incluye la creación y la inicialización de una relación de replicación. Para configurar la replicación, crea la relación de replicación. Para transferir los datos entre los sistemas de almacenamiento de origen y de destino, inicializa la relación de replicación. Al migrar los datos de VM de almacenamiento y los ajustes de configuración, también debes completar la operación de transición.

Los volúmenes replicados en el sistema de archivos de destino son volúmenes de protección de datos (DP) y siguen el formato de nomenclatura: `{OriginalVolumeName}_copy`.

Si replicas un volumen de origen con archivos inmutables, el volumen de destino y el sistema de archivos permanecen bloqueados hasta que termine el periodo de retención del volumen de origen. La función de archivos inmutables está disponible cuando link:create-volume.html["crear un volumen"] para un sistema de archivos FSx for ONTAP.

[NOTE]
====
Puedes replicar un volumen de origen (lectura/escritura) o un volumen de protección de datos (DP). Se admite la replicación en cascada, pero no un tercer salto. Más información sobre link:https://docs.netapp.com/us-en/workload-fsx-ontap/cascade-replication.html["replicación en cascada"].

====


[[migration-use-cases]]
=== Casos de uso de migración

Para la migración, puedes elegir replicar los datos de la VM de almacenamiento y la configuración para una sola VM de almacenamiento. Si migras los datos y la configuración juntos, asegúrate de que la última replicación del volumen haya finalizado en las últimas 24 horas. Debes seleccionar todos los volúmenes en la misma VM de almacenamiento para usar esta función. La política de organización en niveles para todos los volúmenes será, por defecto, la política de organización en niveles del volumen de origen, lo cual se recomienda para casos de uso de migración.

Workload Factory admite la replicación de migración para máquinas virtuales de almacenamiento entre los siguientes sistemas de almacenamiento.

* Sistemas ONTAP locales y FSx para ONTAP file systems
* Cloud Volumes ONTAP y FSx para sistemas de archivos ONTAP
* FSx for ONTAP y sistemas de archivos FSx for ONTAP
+
** De primera a primera generación
** De segunda a segunda generación




Para migrar los datos de la máquina virtual de almacenamiento y los ajustes de configuración, debes completar tres operaciones.

. <<Paso 1: Crear la relación de replicación,Crear la relación de replicación>>, selecciona *Migración* como caso de uso y selecciona *Replicar la configuración de la máquina virtual de almacenamiento*.
. <<Paso 2: inicializa la relación de replicación,Inicializar la relación de replicación>> transferir los datos del sistema de origen al sistema de almacenamiento de destino.
. <<Paso 3: transición de la replicación para casos de migración,Transición de replicación para casos de migración>> para migrar de forma permanente datos y ajustes de configuración del sistema de archivos de origen al sistema de archivos FSx for ONTAP de destino.




[[step-1-create-the-replication-relationship]]
== Paso 1: Crear la relación de replicación

Replica datos entre dos sistemas de archivos FSx for ONTAP, entre un sistema ONTAP local y un sistema de archivos FSx for ONTAP, o entre Cloud Volumes ONTAP y un sistema de archivos FSx for ONTAP.

.Antes de empezar
Revisa estos requisitos antes de empezar.

* Asegúrate de que hay un sistema de archivos FSx para ONTAP disponible para usar como destino en la relación de replicación.
* Abre los puertos TCP 11104 y 11105 para la transferencia de datos segura y la gestión entre sistemas de almacenamiento. ICMP es opcional, pero puede ayudar con las comprobaciones de red y la resolución de problemas.
* El sistema de ficheros FSx for ONTAP que uses para la relación de replicación debe tener un enlace asociado. link:create-link.html["Aprende cómo asociar un enlace existente o crear y asociar un nuevo enlace"^]. Después de asociar el enlace, vuelve a esta operación.
* Para la replicación desde un sistema ONTAP local a un sistema de archivos FSx for ONTAP, asegúrate de haber detectado el sistema ONTAP local.
* La replicación no es compatible con volúmenes en un estado distinto de disponible, creado o mal configurado, y cuando la versión de ONTAP no es compatible.
* Para los casos de uso de migración, asegúrate de que la última replicación para el volumen se haya completado en las últimas 24 horas antes de crear una relación de replicación con los datos y la configuración de la máquina virtual de almacenamiento.


.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa se utiliza para ir a Workloads, la opción del menú de Workload Factory"], *Workloads* > *Storage* > *FSx for ONTAP*.
. En la página de FSx for ONTAP, selecciona el sistema de archivos que contiene los volúmenes que deseas replicar.
. Replica todos los volúmenes de un sistema de archivos o replica solo los volúmenes que selecciones.
+
** Para replicar todos los volúmenes de un sistema de archivos: en la vista general del sistema de archivos, selecciona *Replicar datos*.
** Para replicar determinados volúmenes: en la vista general del sistema de archivos, selecciona la pestaña *Volúmenes*.
+
En la tabla «Volúmenes», selecciona uno o varios volúmenes y a continuación selecciona *Replicar datos*.



. En la página «Replicar datos», en el apartado «Destino de la replicación», introduce lo siguiente:
+
.. *Caso de uso*: selecciona uno de los siguientes casos de uso para la replicación. Dependiendo del caso de uso seleccionado, Workload Factory rellena el formulario con los valores recomendados de acuerdo con las mejores prácticas. Puedes aceptar los valores recomendados o realizar cambios a medida que rellenas el formulario.
+
*** Inteligencia artificial (IA) y aprendizaje automático (ML): replica tus datos ONTAP locales a FSx for ONTAP y crea puntos de acceso S3 para apoyar el entrenamiento de IA y ML en la nube
*** Migración: transfiere tus datos al sistema de archivos FSx for ONTAP de destino
+
*Replicar configuración de VM de almacenamiento*: Opcionalmente, selecciona para replicar los datos y los ajustes de configuración de una sola VM de almacenamiento. Al migrar datos y ajustes, todos los volúmenes deben finalizar la replicación en las últimas 24 horas y luego hacer la transición al mismo tiempo.

+
La política de organización en niveles para todos los volúmenes será, por defecto, la política de organización en niveles del volumen de origen, lo cual se recomienda para casos de uso de migración.

+
Durante la migración, los clientes acceden a los datos del sistema de ficheros ONTAP de origen. Después de la transición, los volúmenes están disponibles a través del FSx para ONTAP de destino mediante las direcciones IP del sistema de ficheros. Actualiza cualquier cliente o recurso que todavía use la dirección IP antigua.

*** Recuperación ante desastres en caliente: garantiza una alta disponibilidad y una rápida recuperación ante desastres para las cargas de trabajo críticas
*** Recuperación ante desastres en frío o de archivo:
+
**** Recuperación ante desastres en frío: utiliza objetivos de tiempo de recuperación (RTO) y objetivos de punto de recuperación (RPO) más largos para reducir los costes
**** Archivo: replica datos para almacenamiento a largo plazo y cumplimiento normativo


*** Otros
+
Además, la selección del caso de uso determina la política de replicación o la política de SnapMirror (ONTAP). Los términos utilizados para describir las políticas de replicación proceden de link:https://docs.netapp.com/us-en/ontap/data-protection/default-protection-policies-concept.html["Documentación de ONTAP 9"^].

+
**** En el caso de la migración y otros casos, la política de replicación se denomina _MirrorAllSnapshots_. _MirrorAllSnapshots_ es una política asíncrona para replicar todas las instantáneas y el último sistema de archivos activo.
**** Para la recuperación ante desastres en caliente, en frío o de archivo, la política de replicación se llama _MirrorAndVault_. _MirrorAndVault_ es una política asíncrona y de vault para reflejar el sistema de archivos activo más reciente y las instantáneas diarias y semanales.
+
En todos los casos de uso, si activas las instantáneas para la retención a largo plazo, la política de replicación predeterminada es _MirrorAndVault_.





.. *Sistema de archivos FSx para ONTAP*: selecciona las credenciales, la región y el nombre del sistema de archivos FSx para ONTAP para el sistema de archivos FSx para ONTAP de destino.
.. *Nombre de VM de almacenamiento*: selecciona la VM de almacenamiento. La VM de almacenamiento que selecciones será el destino de todos los volúmenes seleccionados en esta relación de replicación.
+
Cuando los nombres de las máquinas virtuales de almacenamiento de origen y destino son idénticos, creamos un alias de sistema de archivos para los nombres de las máquinas virtuales de almacenamiento de destino para evitar conflictos de peering.

.. *Nombre del volumen*: el nombre del volumen de destino se genera automáticamente con el siguiente formato `{OriginalVolumeName}_copy`. Puedes usar el nombre de volumen generado automáticamente o introducir otro nombre de volumen.
.. *Política de almacenamiento por niveles*: selecciona la política de almacenamiento por niveles para los datos almacenados en el volumen de destino. La política de almacenamiento por niveles predeterminada es la recomendada para el caso de uso que hayas seleccionado.
+
_Equilibrado (Automático)_ es la política de almacenamiento por niveles predeterminada al crear un volumen mediante la consola de Workload Factory. Para obtener más información sobre las políticas de almacenamiento por niveles de volúmenes, consulta link:https://docs.aws.amazon.com/fsx/latest/ONTAPGuide/volume-storage-capacity.html#data-tiering-policy["Capacidad de almacenamiento de volumen"^] en la documentación de AWS FSx for NetApp ONTAP. Ten en cuenta que Workload Factory usa nombres basados en casos de uso en la consola de Workload Factory para las políticas de almacenamiento por niveles e incluye los nombres de las políticas de almacenamiento por niveles de FSx for ONTAP entre paréntesis.

+
Si has seleccionado el caso de uso de migración, Workload Factory selecciona automáticamente la opción de copiar la política de organización en niveles del volumen de origen al volumen de destino. Puedes desmarcar la opción de copiar la política de organización en niveles y seleccionar una política de organización en niveles que se aplique al volumen seleccionado para la replicación.

.. *Tasa de transferencia máxima*: selecciona *Limitada* e introduce el límite máximo de transferencia en MB/s. También puedes seleccionar *Ilimitada*.
+
Sin un límite, el rendimiento de la red y de las aplicaciones puede disminuir. Como alternativa, recomendamos una tasa de transferencia ilimitada para los sistemas de archivos FSx for ONTAP en cargas de trabajo críticas, por ejemplo, aquellas que se utilizan principalmente para la recuperación ante desastres.



. En Configuración de replicación, introduce lo siguiente:
+
.. *Inicializar relación de replicación*: Elige si quieres inicializar la relación de replicación inmediatamente después de crear la relación de replicación o más tarde. Ten en cuenta que la inicialización puede llevar mucho tiempo y podrías querer ejecutar la transferencia completa en horas de poca actividad.
+
Para inicializar más tarde manualmente, consulta las instrucciones en <<Paso 2: inicializa la relación de replicación,Paso 2: inicializa la relación de replicación>>.

.. *Intervalo de replicación*: selecciona la frecuencia con la que se transfieren las instantáneas del volumen de origen al volumen de destino.
.. *Retención a largo plazo*: Si lo deseas, activa las instantáneas para la retención a largo plazo. La retención a largo plazo permite que los servicios empresariales sigan funcionando incluso en caso de un fallo total del sitio, lo que facilita que las aplicaciones realicen una conmutación por error de forma transparente utilizando una copia secundaria.
+
Las replicaciones sin retención a largo plazo usan la política _MirrorAllSnapshots_. Habilitar la retención a largo plazo asigna la política _MirrorAndVault_ a la replicación.

+
Si activas la retención a largo plazo, selecciona una política existente o crea una nueva para definir las instantáneas que quieres replicar y cuántas conservar.

+

NOTE: Las etiquetas de origen y destino coincidentes son necesarias para la conservación a largo plazo. Si lo deseas, Workload Factory puede crear las etiquetas que falten por ti.

+
*** *Elige una política existente*: selecciona una política existente.
*** *Crear una nueva política*: introduce un *nombre de política*.


.. *Instantáneas inmutables*: Opcional. Selecciona *Habilitar instantáneas inmutables* para evitar que las instantáneas creadas en esta política se eliminen durante el periodo de retención.
+
*** Establece el *período de retención* en número de horas, días, meses o años.
*** *Políticas de Snapshot*: en la tabla, selecciona la frecuencia de la política de Snapshot y el número de copias que deseas conservar. Puedes seleccionar más de una política de Snapshot.


.. *Punto de acceso S3*: opcionalmente, adjunta un punto de acceso S3 para acceder a los datos del sistema de archivos FSx for ONTAP que residen en volúmenes NFS o SMB/CIFS a través de las API de AWS S3. Solo se admite el tipo de acceso a archivos. Proporciona los siguientes detalles:
+
*** *Nombre del punto de acceso S3*: Ingresa el nombre del punto de acceso S3.
*** *Usuario*: selecciona un usuario existente con acceso al volumen o crea un nuevo usuario.
*** *Tipo de usuario*: selecciona *UNIX* o *Windows* como tipo de usuario.
*** *Configuración de red*: selecciona *Internet* o *Virtual private cloud (VPC)*. El tipo de red que elijas determina si el punto de acceso es accesible desde internet o está restringido a una VPC específica.
*** *Habilitar tabla de inventario*: cuando habilitas la tabla de inventario en el volumen, el sistema genera metadatos para todos los objetos accesibles al punto de acceso S3 e incurre en costes de solicitud de AWS S3. Consulta link:https://aws.amazon.com/s3/pricing/["Documentación de precios de Amazon S3"^] para obtener más información.


.. *Etiquetas de punto de acceso S3*: opcionalmente, puedes añadir hasta 50 etiquetas.




. Selecciona *Crear*.


.Resultado
La relación de replicación aparece en la pestaña *Replication relationships* del sistema de archivos FSx for ONTAP de destino.

Si creaste una relación de replicación con fines de migración, debes realizar la transición de todos los volúmenes y su VM de almacenamiento asociada para completar la migración de los datos de la VM de almacenamiento y los ajustes de configuración al sistema de archivos de destino FSx for ONTAP.



[[step-2-initialize-the-replication-relationship]]
== Paso 2: inicializa la relación de replicación

Inicializa una relación de replicación entre los volúmenes de origen y destino para transferir la instantánea y todos los bloques de datos en NetApp Workload Factory.

La inicialización realiza una transferencia completa: realiza una instantánea del volumen de origen y luego transfiere la instantánea y todos los bloques de datos a los que hace referencia al volumen de destino.

.Antes de empezar
Ten en cuenta cuándo quieres completar esta operación. La inicialización puede llevar mucho tiempo. Quizá quieras ejecutar la transferencia completa en las horas de menor actividad.

.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa se utiliza para ir a Workloads, la opción del menú de Workload Factory"], *Workloads* > *Storage* > *FSx for ONTAP*.
. En *FSx para ONTAP*, selecciona el menú de acciones del sistema de ficheros que quieres actualizar y luego selecciona *Manage*.
. En la vista general del sistema de archivos, selecciona la pestaña *Relaciones de replicación*.
. En la pestaña Replication relationships, selecciona el menú de acciones de la relación de replicación que quieres inicializar.
. Selecciona *Inicializar*.
. En el cuadro de diálogo Inicializar relación, selecciona *Inicializar*.
+
Cuando el estado de replicación muestra *Idle*, la transferencia de datos se ha completado.





[[step-3-cut-over-replication-for-migration-use-cases]]
== Paso 3: transición de la replicación para casos de migración

Después de crear la relación de replicación para un caso de uso de migración, debes realizar la transición de la replicación para completar la migración de los datos y los ajustes de configuración de la máquina virtual de almacenamiento al sistema de archivos FSx for ONTAP de destino. La replicación de transición migra permanentemente los datos y los ajustes de configuración de la máquina virtual de almacenamiento desde el sistema de archivos de origen al sistema de archivos FSx for ONTAP de destino. Durante la transición, los datos se replican por última vez. La máquina virtual de almacenamiento de origen se desconecta cuando comienza la transición.



[[plan-for-the-cutover-operation]]
=== Plan para la operación de transición

Ten en cuenta lo siguiente al planificar la operación de transición para los casos de uso de migración.

* *Soporte de la versión de replicación*: los sistemas de almacenamiento de origen y destino deben tener la misma versión principal de ONTAP. Por ejemplo, si el sistema de origen ejecuta ONTAP versión 9.18.1, entonces el sistema de destino también debe ejecutar una versión 9.18.1.
* *Ajustes de configuración de la máquina virtual de almacenamiento*:
+
** La operación de transición no migra todos los ajustes de configuración de la VM de almacenamiento a la VM de almacenamiento de destino. Por ejemplo, los ajustes de iSCSI, MTU de dominio de difusión y DNS no migran. Actualiza estos ajustes manualmente en la VM de almacenamiento de destino después de la transición. Para más detalles, consulta la sección <<Actualiza los parámetros de configuración después de la transición,Actualiza los parámetros de configuración después de la transición>>.
** Si tu máquina virtual de almacenamiento utiliza autenticación de túnel de dominio, configura y activa un túnel de dominio en el sistema de archivos de destino antes de iniciar la migración.


* *Clones*: Los clones se migran como volúmenes individuales y, por tanto, consumirán más espacio en el sistema de archivos FSx para ONTAP de destino. Considera eliminar los clones antes de la transición para evitar un aumento de capacidad en el destino.
* *Volúmenes de caché*: Para ONTAP FlexCache 9.17.x o versiones inferiores. Las máquinas virtuales de almacenamiento de origen que contienen volúmenes de caché no son compatibles con la transición. Elimina la relación de ONTAP FlexCache antes de la transición para evitar fallos en la migración.
* *Puntos de acceso S3 de AWS*: La replicación de transición para casos de uso de migración no es compatible con volúmenes con puntos de acceso S3. Elimina los puntos de acceso S3 del volumen de origen para evitar fallos en la migración.
* *Configuraciones de ONTAP S3*: La replicación de transición para casos de uso de migración no es compatible con vservers con configuraciones de ONTAP S3. Elimina las configuraciones de ONTAP S3, incluyendo object-store-server, buckets, usuarios, grupos o políticas en el vserver, para evitar fallos de migración.
* *Números de serie de LUN y IQN de destino iSCSI*: los números de serie de LUN y el IQN de destino iSCSI cambian durante la transición.


.Antes de empezar
Revisa estos requisitos antes de empezar.

* Detén cualquier acceso de clientes a tu VM de almacenamiento antes de la transición de la replicación.
* Asegúrate de que todos los volúmenes de origen no estén sirviendo ningún dato antes de la transición de la replicación.
* Asegúrate de que los datos estén sincronizados entre los volúmenes de origen y destino antes de realizar la transición de la replicación.
* El sistema de ficheros FSx for ONTAP que uses para la relación de replicación debe tener un enlace asociado. link:create-link.html["Aprende cómo asociar un enlace existente o crear y asociar un nuevo enlace"^]. Después de asociar el enlace, vuelve a esta operación.
+
** Los siguientes puertos deben estar abiertos en el grupo de seguridad asociado al sistema de archivos FSx para ONTAP para la conectividad de enlace: puerto 443 (HTTPS) y puerto 22 (SSH).




.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa se utiliza para ir a Workloads, la opción del menú de Workload Factory"], *Workloads* > *Storage* > *FSx for ONTAP*.
. En *FSx for ONTAP*, selecciona el sistema de archivos que contiene el o los volúmenes que quieres replicar.
. Selecciona la pestaña *Relaciones de réplica*.
. En la tabla de relaciones de replicación, selecciona la relación de replicación para hacer la transición y luego selecciona *Transición de replicación*.
. Revisa la información en el cuadro de diálogo de transición de replicación y luego escribe _cut over_ para confirmar.


. Selecciona *transición*.


.Resultado
Tras iniciar la transición, la máquina virtual de almacenamiento de origen se desconecta.



[[update-configuration-settings-after-cutover]]
=== Actualiza los parámetros de configuración después de la transición

Después de realizar la transición de la replicación para casos de uso de migración, actualiza los siguientes ajustes de configuración de la VM de almacenamiento en la VM de almacenamiento de destino.

* Para iSCSI:
+
** Vuelve a crear el igroup
** Actualizar mapeo LUN
** Inicia sesión en cada cliente SAN y actualiza la configuración iSCSI/MPIO para el nuevo destino y elimina las antiguas IP de destino vserver


* Valida que la configuración de MTU del dominio de difusión es la esperada
* Valida que la configuración DNS es la esperada
* Vuelve a crear las relaciones de caché (relaciones de ONTAP FlexCache) si había volúmenes de caché en la VM de almacenamiento de origen.


Si es necesario, link:change-tiering-policy.html["modifica la política de niveles"] para los volúmenes de destino tras la transición.



[[cascade-replication-for-data-protection-volumes]]
== Replicación en cascada para volúmenes de protección de datos

NetApp Workload Factory admite la replicación de volúmenes de protección de datos, también llamados _implementaciones en cascada_. Una _implementación en cascada_ consiste en una cadena de relaciones en la que un volumen de origen se refleja en un volumen secundario (primer salto) y el volumen secundario se refleja en un volumen terciario (segundo salto). Si el volumen secundario deja de estar disponible, puedes sincronizar la relación entre los volúmenes primario y terciario sin realizar una nueva transferencia completa.

Esta función es compatible con los sistemas de archivos FSx for ONTAP con la versión 9.6 de ONTAP o superior. Consulta link:https://docs.netapp.com/us-en/ontap/data-protection/compatible-ontap-versions-snapmirror-concept.html#snapmirror-disaster-recovery-relationships["Documentación de ONTAP para las versiones compatibles de ONTAP"^].

Más información sobre link:https://docs.netapp.com/us-en/ontap/data-protection/supported-deployment-config-concept.html#how-cascade-deployments-work["cómo funcionan las implementaciones en cascada"^].

.Antes de empezar
Antes de empezar, ten en cuenta lo siguiente:

* Ten en cuenta que los volúmenes que forman parte de una configuración en cascada pueden tardar más en resincronizarse.
* Si el volumen de origen de la relación es un volumen de protección de datos y es destino de otra relación, no es posible revertir la relación de replicación.
* Se admite una réplica de un volumen de protección de datos (o un segundo salto). No se considera una buena práctica crear una segunda réplica de un volumen de protección de datos (o un tercer salto).
* Abre los puertos TCP 11104 y 11105 para la transferencia de datos segura y la gestión entre sistemas de almacenamiento. ICMP es opcional, pero puede ayudar con las comprobaciones de red y la resolución de problemas.


.Pasos
. Inicia sesión en link:https://console.netapp.com["NetApp Console"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa se utiliza para ir a Workloads, la opción del menú de Workload Factory"], *Workloads* > *Storage* > *FSx for ONTAP*.
. En *FSx for ONTAP*, selecciona el menú de acciones del sistema de archivos que contiene el volumen o los volúmenes que quieres replicar y luego selecciona *Manage*.
. En la vista general del sistema de archivos, selecciona la pestaña *Volúmenes*.
. En la tabla «Volúmenes», selecciona uno o varios volúmenes de protección de datos (volúmenes DP o replicados) y, a continuación, selecciona *Replicar datos*.
. En la página «Replicar datos», en el apartado «Destino de la replicación», introduce lo siguiente:
+
.. *Caso de uso*: selecciona uno de los siguientes casos de uso para la replicación. Dependiendo del caso de uso seleccionado, Workload Factory rellena el formulario con los valores recomendados de acuerdo con las mejores prácticas. Puedes aceptar los valores recomendados o realizar cambios a medida que rellenas el formulario.
+
*** Inteligencia artificial (IA) y aprendizaje automático (ML): replica tus datos ONTAP locales a FSx for ONTAP y crea puntos de acceso S3 para apoyar el entrenamiento de IA y ML en la nube
*** Migración: transfiere tus datos al sistema de archivos FSx for ONTAP de destino
+
*Replicar configuración de VM de almacenamiento*: Opcionalmente, selecciona para replicar los datos y los ajustes de configuración de una sola VM de almacenamiento. Al migrar datos y ajustes, todos los volúmenes deben finalizar la replicación en las últimas 24 horas y luego hacer la transición al mismo tiempo.

+
La política de organización en niveles para todos los volúmenes será, por defecto, la política de organización en niveles del volumen de origen, lo cual se recomienda para casos de uso de migración.

+
Durante la migración, los clientes acceden a los datos del sistema de ficheros ONTAP de origen. Después de la transición, los volúmenes están disponibles a través del FSx para ONTAP de destino mediante las direcciones IP del sistema de ficheros. Actualiza cualquier cliente o recurso que todavía use la dirección IP antigua.

*** Recuperación ante desastres en caliente: garantiza una alta disponibilidad y una rápida recuperación ante desastres para las cargas de trabajo críticas
*** Recuperación ante desastres en frío o de archivo:
+
**** Recuperación ante desastres en frío: utiliza objetivos de tiempo de recuperación (RTO) y objetivos de punto de recuperación (RPO) más largos para reducir los costes
**** Archivo: replica datos para almacenamiento a largo plazo y cumplimiento normativo


*** Otros
+
Además, la selección del caso de uso determina la política de replicación o la política de SnapMirror (ONTAP). Los términos utilizados para describir las políticas de replicación proceden de link:https://docs.netapp.com/us-en/ontap/data-protection/default-protection-policies-concept.html["Documentación de ONTAP 9"^].

+
**** En el caso de la migración y otros casos, la política de replicación se denomina _MirrorAllSnapshots_. _MirrorAllSnapshots_ es una política asíncrona para replicar todas las instantáneas y el último sistema de archivos activo.
**** Para la recuperación ante desastres en caliente, en frío o de archivo, la política de replicación se llama _MirrorAndVault_. _MirrorAndVault_ es una política asíncrona y de vault para reflejar el sistema de archivos activo más reciente y las instantáneas diarias y semanales.
+
En todos los casos de uso, si activas las instantáneas para la retención a largo plazo, la política de replicación predeterminada es _MirrorAndVault_.





.. *Sistema de archivos FSx para ONTAP*: selecciona las credenciales, la región y el nombre del sistema de archivos FSx para ONTAP para el sistema de archivos FSx para ONTAP de destino.
.. *Nombre de VM de almacenamiento*: selecciona la VM de almacenamiento. La VM de almacenamiento que selecciones será el destino de todos los volúmenes seleccionados en esta relación de replicación.
+
Cuando los nombres de las máquinas virtuales de almacenamiento de origen y destino son idénticos, creamos un alias de sistema de archivos para los nombres de las máquinas virtuales de almacenamiento de destino para evitar conflictos de peering.

.. *Nombre del volumen*: el nombre del volumen de destino se genera automáticamente con el siguiente formato `{OriginalVolumeName}_copy`. Puedes usar el nombre de volumen generado automáticamente o introducir otro nombre de volumen.
.. *Política de almacenamiento por niveles*: selecciona la política de almacenamiento por niveles para los datos almacenados en el volumen de destino. La política de almacenamiento por niveles predeterminada es la recomendada para el caso de uso que hayas seleccionado.
+
_Equilibrado (Automático)_ es la política de almacenamiento por niveles predeterminada al crear un volumen mediante la consola de Workload Factory. Para obtener más información sobre las políticas de almacenamiento por niveles de volúmenes, consulta link:https://docs.aws.amazon.com/fsx/latest/ONTAPGuide/volume-storage-capacity.html#data-tiering-policy["Capacidad de almacenamiento de volumen"^] en la documentación de AWS FSx for NetApp ONTAP. Ten en cuenta que Workload Factory usa nombres basados en casos de uso en la consola de Workload Factory para las políticas de almacenamiento por niveles e incluye los nombres de las políticas de almacenamiento por niveles de FSx for ONTAP entre paréntesis.

+
Si has seleccionado el caso de uso de migración, Workload Factory selecciona automáticamente la opción de copiar la política de organización en niveles del volumen de origen al volumen de destino. Puedes desmarcar la opción de copiar la política de organización en niveles y seleccionar una política de organización en niveles que se aplique al volumen seleccionado para la replicación.

.. *Tasa de transferencia máxima*: selecciona *Limitada* e introduce el límite máximo de transferencia en MB/s. También puedes seleccionar *Ilimitada*.
+
Sin un límite, el rendimiento de la red y de las aplicaciones puede disminuir. Como alternativa, recomendamos una tasa de transferencia ilimitada para los sistemas de archivos FSx for ONTAP en cargas de trabajo críticas, por ejemplo, aquellas que se utilizan principalmente para la recuperación ante desastres.



. En Configuración de replicación, introduce lo siguiente:
+
.. *Inicializar relación de replicación*: Elige si quieres inicializar la relación de replicación inmediatamente después de crear la relación de replicación o más tarde. Ten en cuenta que la inicialización puede llevar mucho tiempo y podrías querer ejecutar la transferencia completa en horas de poca actividad.
+
Para inicializar más tarde manualmente, consulta las instrucciones en <<Paso 2: inicializa la relación de replicación,Paso 2: inicializa la relación de replicación>>.

.. *Intervalo de replicación*: selecciona la frecuencia con la que se transfieren las instantáneas del volumen de origen al volumen de destino.
.. *Retención a largo plazo*: Si lo deseas, activa las instantáneas para la retención a largo plazo. La retención a largo plazo permite que los servicios empresariales sigan funcionando incluso en caso de un fallo total del sitio, lo que facilita que las aplicaciones realicen una conmutación por error de forma transparente utilizando una copia secundaria.
+
Las replicaciones sin retención a largo plazo usan la política _MirrorAllSnapshots_. Habilitar la retención a largo plazo asigna la política _MirrorAndVault_ a la replicación.

+
Si activas la retención a largo plazo, selecciona una política existente o crea una nueva para definir las instantáneas que quieres replicar y cuántas conservar.

+

NOTE: Las etiquetas de origen y destino coincidentes son necesarias para la conservación a largo plazo. Si lo deseas, Workload Factory puede crear las etiquetas que falten por ti.

+
*** *Elige una política existente*: selecciona una política existente.
*** *Crear una nueva política*: introduce un *nombre de política*.


.. *Instantáneas inmutables*: Opcional. Selecciona *Habilitar instantáneas inmutables* para evitar que las instantáneas creadas en esta política se eliminen durante el periodo de retención.
+
*** Establece el *período de retención* en número de horas, días, meses o años.
*** *Políticas de Snapshot*: en la tabla, selecciona la frecuencia de la política de Snapshot y el número de copias que deseas conservar. Puedes seleccionar más de una política de Snapshot.


.. *Punto de acceso S3*: opcionalmente, adjunta un punto de acceso S3 para acceder a los datos del sistema de archivos FSx for ONTAP que residen en volúmenes NFS o SMB/CIFS a través de las API de AWS S3. Solo se admite el tipo de acceso a archivos. Proporciona los siguientes detalles:
+
*** *Nombre del punto de acceso S3*: Ingresa el nombre del punto de acceso S3.
*** *Usuario*: selecciona un usuario existente con acceso al volumen o crea un nuevo usuario.
*** *Tipo de usuario*: selecciona *UNIX* o *Windows* como tipo de usuario.
*** *Configuración de red*: selecciona *Internet* o *Virtual private cloud (VPC)*. El tipo de red que elijas determina si el punto de acceso es accesible desde internet o está restringido a una VPC específica.
*** *Habilitar tabla de inventario*: cuando habilitas la tabla de inventario en el volumen, el sistema genera metadatos para todos los objetos accesibles al punto de acceso S3 e incurre en costes de solicitud de AWS S3. Consulta link:https://aws.amazon.com/s3/pricing/["Documentación de precios de Amazon S3"^] para obtener más información.


.. *Etiquetas de punto de acceso S3*: opcionalmente, puedes añadir hasta 50 etiquetas.


. Selecciona *Crear*.


.Resultado
El volumen o los volúmenes replicados aparecen en la pestaña *Relaciones de replicación* del sistema de archivos FSx for ONTAP de destino.
