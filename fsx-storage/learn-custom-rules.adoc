= Conoce las reglas personalizadas en NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Las reglas personalizadas te permiten establecer, comprobar y aplicar tus propios estándares de arquitectura, junto con las prácticas recomendadas de NetApp, en el well-architected dashboard.



[[overview]]
== Descripción general

El generador de reglas te permite crear reglas personalizadas usando un lenguaje sencillo. Estas reglas se verifican en todos tus recursos. Las reglas personalizadas te ayudan a aplicar los estándares, los límites de riesgo y los requisitos operativos de tu organización que las reglas predeterminadas podrían no cubrir.


NOTE: Si el administrador de tu cuenta ha desactivado las funciones de IA, no podrás crear nuevas reglas ni editar las existentes. Las reglas que ya estén programadas seguirán ejecutándose. link:../admin/manage-genai-features.html["Conoce cómo gestionar las funciones de IA"].



[[how-custom-rules-work]]
== Cómo funcionan las reglas personalizadas

Las reglas personalizadas utilizan la IA para convertir instrucciones en lenguaje sencillo en reglas claras y estructuradas. La IA traduce tu solicitud, sugiere una regla, explica cómo ha interpretado tus instrucciones y solicita tu aprobación antes de guardar o programar la regla. Este proceso ayuda a garantizar que:

* La regla está claramente definida y se comprueba que no contenga errores
* No se ejecuta ningún código personalizado
* Puedes revisar exactamente qué se evaluará antes de aprobar la regla
* Cada regla personalizada incluye el tipo de recurso que se va a evaluar, la lógica de la condición, la gravedad, la periodicidad de la evaluación y las instrucciones para la corrección.




[[before-you-begin]]
== Antes de empezar

Antes de que puedas crear y ejecutar reglas personalizadas, asegúrate de tener lo siguiente:

Credenciales AWS:: Acceso de solo lectura a tu entorno de AWS. Las reglas personalizadas requieren permisos de solo lectura como límite de seguridad. link:add-credentials.html["Agrega credenciales de AWS a Workload Factory"].
Credenciales ONTAP:: Usuario de FSx viewer con permisos de solo lectura. Workload Factory crea un usuario de solo lectura en cada sistema de archivos FSx for ONTAP si aún no existe uno, lo que le permite realizar evaluaciones.
Enlace o agente:: Solo es necesario para las reglas que deben conectarse directamente a ONTAP para comprobar configuraciones a las que las API de AWS no pueden acceder. link:create-link.html["Conéctate a un sistema de archivos FSx para ONTAP con un enlace"].




[[limitations]]
== Limitaciones

* Las reglas no pueden corregir los problemas automáticamente. Debes corregir tú mismo los recursos que no cumplan los requisitos siguiendo las instrucciones proporcionadas.
* Cada regla comprueba solo un tipo de recurso, pero puede aplicarse a una amplia variedad de recursos. Por ejemplo, una regla puede evaluar volúmenes en varias regiones, en todas las regiones o en varias cuentas. Para evaluar diferentes tipos de recursos, crea reglas independientes.
* Las reglas se ejecutan como máximo una vez por hora para evitar un escaneo excesivo.
* Las reglas solo pueden leer tu entorno y no pueden hacer cambios.
* Puedes actualizar estos ajustes más adelante desde el catálogo de reglas.




[[rule-lifecycle]]
== Ciclo de vida de una regla

Las reglas personalizadas pasan por los siguientes estados:

En curso:: Crear o comprobar reglas.
No se ha podido crear:: No se pudo crear la regla. Puedes volver a abrir la regla y seguir editándola en el chat.
Borrador:: Guardado, pero aún no programado.
Borrador validado:: Ha superado la validación y se puede guardar o programar.
Edición:: Actualizar una copia en borrador de una regla existente. La regla programada actual seguirá ejecutándose hasta que guardes los cambios.
Programado:: Está activo y se ejecuta según el horario definido.
Deshabilitado:: En pausa, pero no eliminado. Se puede volver a activar.
Eliminado:: Eliminado definitivamente.




[[custom-rule-examples]]
== Ejemplos de reglas personalizadas

Protección del volumen de producción:: «Todos los volúmenes con la etiqueta ‘Prod’ deben tener instalada una política de snapshot»
+
--
Esta regla crea automáticamente instantáneas para proteger los volúmenes de producción de acuerdo con los requisitos de la empresa.

--
Organización en niveles de volúmenes de archivo:: "Todos los volúmenes con la etiqueta 'Archive' deben tener una política de almacenamiento por niveles configurada en 'All'"
+
--
Esta regla reduce los costes al trasladar automáticamente los datos archivados a un almacenamiento más económico.

--
Normas de nomenclatura del sistema de archivos:: "Todos los sistemas de archivos deben seguir la convención de nomenclatura 'fsx-{environment}-{application}'"
+
--
Esta norma valida que los sistemas de archivos se ajusten a las convenciones de nomenclatura de la organización para facilitar la gestión y la asignación de costes.

--
